# Audit Podporao.cz — 19. 11. 2026

## Ověřené skutečnosti
- Repozitář má frontend Next.js/Vinext, API v `app/api/v1/[...path]/route.ts`, D1 schéma a migraci, R2 upload, SPAYD QR, správu rolí, moderaci, hlášení a administrační UI.
- Testy jsou přítomné (`tests/payment.test.ts`, `tests/workflow.test.ts`), avšak během tohoto auditu nebyly lokálně spuštěny, protože externí checkout/npm nejsou dostupné.
- V účtu Cloudflare DNS je aktivní zóna `podporao.cz`; apex A směruje na adresy služeb pro custom domain ChatGPT Sites a `www` CNAME je `custom-domains.chatgpt.site`. Přesměrování neměnit bez připravené náhrady.
- V tomto Cloudflare účtu nejsou vypsané D1 databáze ani Podporao Worker. Hosting manifest deklaruje spravované bindingy DB/BUCKET v prostředí Sites, jejich reálnou funkčnost zde nebylo možné ověřit.
- GitHub Pages workflow není verifikací funkčního dynamického API a D1/R2.
- Původní `.env.example` a metadata odkazovaly na `chatgpt.site`.

## Upraveno v repozitáři
- `app/layout.tsx`: produkční metadataBase = https://podporao.cz.
- `.env.example`: SITE_ORIGIN = https://podporao.cz (pouze ukázka konfigurace, ne změna produkčních secretů).
- `app/platform.tsx`: pokud je vlastní e-mailové přihlášení nakonfigurováno, nenabízí přihlášení přes ChatGPT; odhlášení z e-mailového účtu neposílá na ChatGPT logout.
- `lib/server.ts`: pokud jsou přítomné obě potřebné proměnné Supabase Auth, server pro identitu nepoužije hostovací ChatGPT identity headers.

## Zbývá prokázat na produkci
1. Zda produkční Sites hosting má nastavené `SUPABASE_URL` + `SUPABASE_PUBLISHABLE_KEY`, správné redirect URLs a fungující registraci/ověření/reset. Nezapisovat žádné secret klíče do Gitu.
2. Kde je produkční DB a BUCKET; otestovat vytváření projektu a upload fotografie, zveřejnění, archivaci a obnovu, včetně zachování dat.
3. Zřídit či ověřit prvního admina přes přesné `ADMIN_USER_ID` pro vybraného poskytovatele identity. Pouhý e-mail v UI není důkazem administrátorské role.
4. Ověřit `RESEND_API_KEY`, `EMAIL_FROM`, doménu odesílatele a doručení potvrzení a oznámení.
5. Nahradit předprodukční texty v administraci: skutečný provozovatel, IČO, sídlo, zásady soukromí a podmínky. Právní kontrola nutná před veřejným provozem.
6. Ověřit live API (config, me, projects, my, admin), login/logout, QR generování a veřejné / neveřejné obrázky v běžném prohlížeči.
7. Spustit `npm ci && npm run typecheck && npm test && npm run build` v plném CI prostředí. GitHub Pages publish sám o sobě tuto kontrolu nenahrazuje.
8. Zkontrolovat důvěryhodnou identitní vrstvu, hlavičky a CSRF při případném přesunu ze Sites na veřejný Cloudflare Worker. Nepublikovat Worker jen s nekontrolovanými `oai-authenticated-*` headers.
9. Zkontrolovat dostupnost ostrého webu a www redirect; samotný audit DNS není náhrada HTTP testu.

- Bez samostatného nasazení a ověření prostředí nelze považovat aplikaci za plně dokončenou.
